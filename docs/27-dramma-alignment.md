# انطباق محتوای پخته با DRAMMA

۱۴ نوامبر ۲۰۲۶؛ درخواست مالک این است که تفریح‌های ایرانی و همهٔ تفریح‌های قابل پیشنهاد از DRAMMA پیروی کنند. این سند قرارداد جاری B04/B05/B09 است.

## مبنا و حدود

مدل شش‌نیازی مرجع S2 در [منابع](19-sources.md) مبناست: فاصله‌گرفتن از مشغلهٔ کار، استراحت، اختیار، یادگیری و تسلط، معنا و ارتباط. این‌ها هدف و سازوکار احتمالی تجربه‌اند؛ نوع مکان یا نام فعالیت به‌تنهایی آن‌ها را تعیین نمی‌کند. لازم نیست هر فعالیت هر شش بُعد را پوشش دهد یا تعداد محتوای پخته در بُعدها برابر باشد. سهم۷۵تایی بانک خام، تصمیم اولیهٔ بانک است.

نگاشت این بسته تفسیر محتوایی است، نه اعتبارسنجی تجربی فعالیت‌ها یا تضمین اثر روانی. validator فقط ساختار، تطابق بُعدها، ارجاع قدم‌ها و شرط اجرای مشترک را کنترل می‌کند؛ کیفیت معنایی دلیل همچنان نیازمند بررسی انسان است. `origin=demo` و `human_approval=false` حفظ شده‌اند. هیچ تولید پولی مدل انجام نشده است.

## قرارداد محتوا

`Content.dramma` اجباری است؛ `version=dramma_v1` و `mechanisms` شامل یک تا چهار سازوکار است. هر سازوکار `dimension`، دلیل فارسی مشخص `intent` با طول۱۵تا۲۴۰ و `step_indexes` دارد. شمارهٔ قدم‌ها یک‌مبناست و به `steps` همین نسخه اشاره می‌کند؛ نه `first_step` یا مراحل برنامه‌ای دیگر. تکرار بُعد/قدم، قدم خارج محدوده، boolean به‌جای شماره، نبود دلیل و اختلاف مجموعهٔ سازوکارها با primary+secondary رد می‌شود. primary محتوا باید با activity یکی باشد.

در این نسخه، ادعای affiliation به تعامل متقابل در اجرای `together` محدود است. محتوایی که اجرای solo هم دارد باید نسخهٔ جدا برای ارتباط داشته باشد؛ صرف حضور در کنسرت یا برخورد خدماتی با فروشنده کافی نیست. این محدودیت عملیاتی، ادعای انحصاری دربارهٔ نظریه نیست.

ثبت ویرایش، خروجی provider، ارسال به بررسی و انتشار از همین Pydantic استفاده می‌کنند. کاتالوگ پیشنهاد محتوای قدیمی فاقد قرارداد را کنار می‌گذارد و شروع نیز دوباره همان شرط را بررسی می‌کند. نسخهٔ قدیمی در تاریخچه قابل استناد می‌ماند. ادمین، دلیل و متن قدم‌های مرتبط را می‌بیند؛ کارت عادی حروف DRAMMA و گزارش فنی را نشان نمی‌دهد.

## محتوای اصلاح‌شده

همهٔ۴۳۱ محتوای پختهٔ مخزن، شامل۳۰۰ تفریح ایران و۱۸ نمونهٔ بایگانی‌شده، و شش قالب پخت نمایشی با قرارداد کامل ثبت شدند.۴۵۰ بذر خام همچنان پیش‌نویس غیرفعال‌اند؛ نگاشت بانک به بُعد، آن‌ها را محتوای پخته یا منتشرشده نمی‌کند.

نگاشت۳۰۰ فعالیت در [iran-dramma.json](../content/iran-dramma.json) با کلید مستقل هر دستور اجرا نگهداری می‌شود. generator دقیقاً همان۳۰۰ کلید را می‌خواهد؛ برای هر گروه یک بُعد ثابت حدس نمی‌زند. مثال‌ها: سینما برای فاصله از مشغله، تئاتر تعاملی برای اختیار، کاپینگ هدایت‌شده برای یادگیری، چایخانه با ریتم بدون فشار برای استراحت و بازی همکاری دونفره برای ارتباط. دوخت و چاپ به‌صورت عمومی «معنا» نگرفته‌اند؛ نسخه‌های معنا باید به علاقه یا ارزش مشخص شخصی پیوند داشته باشند. در محتوای قدیمیِ معنا نیز قدم اجرایی مربوط تقویت شد.

این تعداد شامل محتواهای بایگانی‌شده هم هست؛ تعداد فعال اولیه۴۱۳ است. قیمت و موجودی برنامه‌ها تأیید زنده نشده‌اند؛ رضایت بررسی محل، بودجهٔ flexible و همهٔ فیلترهای [26](26-iran-paid-catalog.md) برقرارند.

## ارتقای دادهٔ موجود

با `DEMO_CONTENT=true`، پس از readiness واقعی Mongo، seed جدید و ارتقای idempotent اجرا می‌شوند. فقط نسخهٔ جاری published از origin demo که دقیقاً با checksum محتوای قبلیِ ارسال‌شده برابر باشد، فعال باشد، کنار گذاشته نشده و تأیید انسانی نداشته باشد، واجد ارتقاست. checksumهای قبل از تغییر در [فایل مهاجرت](../content/dramma-legacy-checksums.json) ثبت شده‌اند. Docker و ZIP این فایل را همراه دارند.

هر اصلاح یک revision جدید با شمارهٔ تازه می‌سازد؛ نسخهٔ قدیمی superseded می‌شود و متن و snapshotهای قبلی دست‌نخورده می‌مانند. pointer و بُعد activity در همان transaction با کنترل نسخه و audit عوض می‌شوند. دادهٔ ویرایش‌شده، منشأ انسانی، تأییدشده، inactive و withdrawn بازنویسی یا فعال نمی‌شوند. نسخه‌های انسانی قدیمیِ نامنطبق باید در ادمین clone، تکمیل، بررسی و منتشر شوند؛ تا آن زمان وارد پیشنهاد یا شروع جدید نمی‌شوند. اجرای دوباره revision تکراری نمی‌سازد و بذر خام را منتشر نمی‌کند.

## تولید و بررسی محلی

```bash
.venv/bin/python scripts/build-iran-catalog.py
.venv/bin/python scripts/export-activities.py
PYTHONPATH=apps/api .venv/bin/python -m unittest discover -s apps/api/tests -v
cd apps/web
npm test
npm run typecheck
npm run build
```

برای اجرای محصول از فرمان‌های Mongo عمومی در README و سند24 استفاده شود؛ اجرای حافظه‌ای فقط double صریح تست است. خروجی JSON و CSV شامل دلیل و شمارهٔ قدم‌های DRAMMA است. بستهٔ ارسال با `scripts/package-deploy.py` بازتولید می‌شود.

نتیجهٔ محلی: `unittest` تعداد۱۴۵ تست را گزارش کرد؛۱۳۸ موفق و۷ آزمون Mongo زنده skip شدند. پوشش شامل قرارداد DRAMMA، خروجی نامعتبر provider، مرز بررسی/انتشار، شروع از پیشنهاد قدیمی، مهاجرت نسخه‌ای، فیلترهای سخت، نشست/CSRF، مالکیت افقی و هم‌زمانی پایان است.۱۹ تست فرانت، TypeScript و ساخت production نیز موفق بودند. بازتولید۳۰۰ دستور و خروجی‌های۸۸۱ فعالیت/۴۳۱ محتوای پخته/۶ قالب و ZIP انجام شد. این نتیجه جایگزین E2E یا آزمون زنده نیست.

در این محیط driver قفل‌شدهٔ PyMongo نصب نیست؛ `diagnose-db` همین مانع را گزارش می‌کند. مهاجرت در Mongo زنده، استقرار Docker، E2E مرورگر و بررسی انسانیِ انتشار عمومی انجام نشده‌اند.
