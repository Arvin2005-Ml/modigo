# جریان، متن و حالت‌های رابط

## نقشهٔ مسیرها

| مسیر وب | وظیفه |
| --- | --- |
| `/` | معرفی کوتاه و دعوت اصلی |
| `/login`, `/signup`, `/forgot-password`, `/reset-password` | هویت |
| `/app` | خانهٔ کاربر |
| `/app/check-in` | سؤال‌های موقعیتی |
| `/app/suggestions/[sessionId]` | نتیجه و تعویض کارت |
| `/app/activities/[revisionId]` | جزئیات همان نسخهٔ دیده‌شده |
| `/app/experiences/[id]` | وضعیت اجرا و پایان |
| `/app/saved`, `/app/history`, `/app/journey` | ذخیره‌ها، سابقه و مسیر اکتشاف |
| `/app/settings` | ترجیحات، حریم خصوصی و حساب |
| `/admin/...` | مسیرهای سند ادمین |

احراز هویت لازم برای همهٔ `/app` و `/admin`؛ لندینگ عمومی. `next` پس از ورود فقط مسیر داخلی مجاز باشد. پاسخ سؤال‌ها در حافظه/sessionStorage همان تب حفظ شود؛ پس از ارسال موفق یا logout پاک شود؛ حال و بودجه در URL و localStorage دائمی نباشند.

## لحن

جمله‌های کوتاه، بدون لحن درمانگر یا مربی بهره‌وری. نه کودکانه و نه رسمی خشک. دعوت به انتخاب با حق ردکردن. emoji در متن اصلی نیاز نیست. «اگه خواستی» مناسب‌تر از «باید» در پیشنهادهای تفریح است. متن خطای ورودی دقیق و محترمانه باشد.

| موقعیت | متن نمونه |
| --- | --- |
| شروع | «ببینیم الان چی می‌چسبه.» |
| راهنمای وقت | «رفت‌وآمد و آماده‌شدن هم از همین وقته.» |
| حال اختیاری | «اگه نمی‌خوای بگی، ردش کن.» |
| منتظر نتیجه | «داریم گزینه‌های مناسب رو می‌چینیم…» |
| پایان | «این وقت برای خودت بود.» |
| بازگشت بعد از غیبت | «خوش اومدی. امروز چی می‌چسبه؟» |
| بودجه نامعتبر | «سقف هزینه رو به تومان و با عدد مثبت بنویس.» |
| ذخیره ناموفق | «ذخیره نشد. دوباره امتحان کنیم.» |
| نشست منقضی | «برای ادامه دوباره وارد شو. پاسخ‌هات همین‌جا می‌مونه.» |
| محتوای برداشته‌شده | «این پیشنهاد فعلاً در دسترس نیست. یه گزینهٔ دیگه ببینیم.» |

از «درمان اضطراب»، «تضمین شادی»، «تو افسرده‌ای»، «امروز عقب افتادی» و شمارش روزهای از دست‌رفته استفاده نشود.

## قرارداد تعامل

در هر صفحه یک کار اصلی. برگشت وضعیت قبلی را حفظ کند. submit در حال ارسال غیرفعال و دارای وضعیت قابل خواندن باشد؛ idempotency سرور همچنان لازم است. حفظ‌کردن یا پایان‌دادن فقط پس از پاسخ موفق سرور تأیید قطعی شود. ذخیره می‌تواند optimistic باشد ولی rollback و اعلان خطا لازم است.

کارت به‌صورت container همراه پیوند عنوان و دکمه‌های مجزا باشد؛ دکمه داخل لینک کلی یا عنصر کلیک‌پذیر تو‌در‌تو نساز. منوی overflow با keyboard کار کند. نمایش skeleton کوتاه و ثابت؛ خطا جایگزین shimmer بی‌پایان شود. پیشنهاد از کاتالوگ منتشرشده می‌آید و انتظارِ پاسخ مدل ندارد. صفحهٔ نتیجه یک کارت دارد؛ مرور قبلی/بعدی بدون مصرف سهمیه است و کارت قبلی پس از برگشت قابل شروع می‌شود. شمارنده و جای مرور فقط پس از پاسخ موفق سرور تغییر می‌کنند؛ دریافت گزینهٔ تازه تا شش بار و در انتهای تاریخچه است.

## دسترس‌پذیری

هدف WCAG 2.2 AA؛ صحت با ابزار و تست دستی بررسی شود. کنتراست متن عادی حداقل 4.5:1؛ متن ریز کم‌رنگ ممنوع. focus واضح، ترتیب منطقی DOM در RTL، کنترل‌های حداقل ۴۴ پیکسل، label واقعی، شرح خطا و live region برای وضعیت لازم است. حرکت کاهش‌یافته رعایت شود. رنگ تنها نشانهٔ انتخاب، وضعیت یا بُعد نیست.

در موبایل header ثابت عظیم نداریم؛ نوار پایین سه گزینهٔ «امروز»، «ذخیره‌ها»، «مسیر من» و تنظیمات در header. صفحهٔ تجربهٔ فعال از header قابل بازگشت است. ادمین layout جدا با sidebar جمع‌شونده دارد. کاربران کم‌بینا یا با نیاز حرکتی باید با ترجیح اختیاری خود فیلتر سخت اعمال کنند؛ از روی mood حدس نزن.
