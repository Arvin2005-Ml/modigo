## مواردی که پیش از عرضه عمومی باید معلوم شوند

نام و هویت برند نهایی؛ مالکیت و منشأ بانک موجود در صورت تحویل؛ حوزهٔ جغرافیایی و شرایط قانونی؛ هزینه و سیاست نگهداری GapGPT؛ SMTP و دامنه؛ محتواهای انتشارِ تأییدشده؛ سیاست پشتیبانی و حذف حساب. این‌ها ساخت محلی با demo را مسدود نمی‌کنند. واردکردن secret یا اطلاعات حساب واقعی در سند راه‌حل این موارد نیست.

## اصلاحات سازگاری

هر تغییر در enum،fields،API،حساب امتیاز یا retention باید ابتدا در سند مرجع و سپس در سندهای مصرف‌کننده اعمال شود. نسخهٔ algorithm/rewards/prompt و migration مرتبط ثبت شود. تغییر فقط در متن UI قرارداد backend را عوض نمی‌کند.

## شروع پیاده‌سازی — ۲۰۲۶-۱۱-۰۶

مالک صراحتاً شروع ساخت نرم‌افزار را خواسته است؛ محدودیت بستهٔ اولیه به مستندسازی دیگر مانع شروع نیست. به‌علت نبود دسترسی به registry بسته‌ها و Docker daemon در محیط فعلی، انتخاب و قفل وابستگی‌های قابل نصب، Compose و آزمون integration هنوز تکمیل نشده‌اند. از نسخهٔ قدیمی cacheشدهٔ Next.js استفاده نشده است؛ پیش‌نمایش مستقل HTML صرفاً برای بررسی طراحی است و جایگزین Next.js یا API واقعی نیست. پس از رفع دسترسی، Next.js پشتیبانی‌شده و FastAPI/PyMongo با نسخه‌های سازگار انتخاب و lockfile واقعی تولید می‌شود. قبل از اتصال منطق فیلتر به API، DTOهای سخت‌گیر، وضعیت انتشار و داده‌های تاریخ‌دار باید اعتبارسنجی شوند.

## اصلاح جاری به درخواست مالک

Mongo فعلاً با مخزن حافظه‌ای جایگزین می‌شود؛انتخاب PyMongo،migration،replica set و تست اتصال از برنامهٔ جاری حذف و به فاز آینده منتقل شدند. نبود Docker دیگر مانع فاز ماک نیست. محدودیت دسترسی به registry بسته‌ها جداست و این تغییر ادعای حل آن را ندارد. پایهٔ مخزن ماک و هفت تست آن اضافه شدند؛همراه شش تست قبلی،۱۳تست موفق. API و مسیر کامل محصول هنوز به این store وصل نشده‌اند. مرجع اجرا [21](21-mock-storage.md) است.

## تصمیم اجرایی: نمونهٔ پخت محدود و قفل پایتون ۳٫۱۴ — ۷ نوامبر ۲۰۲۶

حالت پیش‌فرض مدل صرفاً از شش محتوای محلی مرتبط با شناسهٔ بذر استفاده می‌کند؛ برای سایر بذرها با خطای صریح پایان می‌یابد و تولید ساختگی یا خروجی مدل محسوب نمی‌شود. بقیهٔ بانک پیش‌نویس خام می‌ماند. provider اختیاری GapGPT طبق نمونهٔ مالک پیاده شده ولی بدون کلید آزمون زنده نشده است. صف در حافظه با worker واحد، پیش‌نویس مقصد و نسخهٔ مورد انتظار را نگه می‌دارد و نتیجهٔ لغوشده یا قدیمی را اعمال نمی‌کند. قابلیت‌های فراتر از این برش در بک‌لاگ ثبت شده‌اند.

به دلیل قفل وابستگی‌های آزمایش‌شده بر محیط Python 3.14، محدودیت فعلی API به ۳٫۱۴ محدود شد؛ پشتیبانی نسخه‌های دیگر نیازمند نصب مستقل و lock مناسب همان محیط است. نصب تازه از registry در این محیط تأیید نشده است.

## تصمیم مالک: حذف تأیید ایمیل از ثبت‌نام محلی — ۸ نوامبر ۲۰۲۶

ثبت‌نام با ایمیل و رمز، بدون لینک تأیید و با ورود مستقیم پس از ساخت حساب انجام می‌شود. مالکیت ایمیل بررسی نمی‌شود و فیلد `email_verified` به‌دروغ true نمی‌شود. بازیابی رمز فعلاً فقط از صندوق محلی اپراتور استفاده می‌کند و ارسال ایمیل واقعی ندارد. این تصمیم بر متن‌های قدیمی نیازمند تأیید در سایر اسناد تقدم دارد و مربوط به اجرای محلی است؛ انتشار عمومی و سازوکار بازیابی آن نیازمند تصمیم جداگانه‌اند.

## اصلاح پوشش و کیفیت پیشنهاد به درخواست مالک — ۹ نوامبر ۲۰۲۶

علت کمبود، فعال‌بودن فقط ۲۴ نمونه و تمرکز آن‌ها بر خانه، تنهایی و فعالیت‌های ذهنی کوتاه بود. برای اصلاح برگشت‌پذیر همین برش، ۱۰۷ تجربهٔ صریح محلی در `content/demo-catalog.json` تألیف شد و هجده نمونهٔ خیلی کلی و مشابه از بانک فعال کنار رفت؛ شش نمونهٔ اصلی حفظ شدند و کاتالوگ اکنون ۱۱۳ تجربهٔ فعال دارد. کلیدهای قبلی عوض نشدند، نمونه‌های کنارگذاشته‌شده archived هستند و import تکراری آن‌ها را فعال نمی‌کند. ۴۵۰ بذر مالک همچنان draft است؛ review انسانی یا خروجی مدل جعل نشده است.

شش گزینه برای ترکیب‌های پایهٔ تست‌شده هدف قرار گرفت، بدون تغییر hard filterها، قرارداد داده، سقف شش کارت، taxonomy یا وزن‌های رتبه‌بندی. انتخاب اختیاری علاقه/هدف/وسایل از قرارداد موجود به UI وصل شد؛ ترجیحات حساب پیش‌فرض و مقدار خالی صریح انتخاب همان نوبت است. با تغییر تنظیمات، check-in ذخیره‌شدهٔ فرانت کنار گذاشته می‌شود تا ترجیحات تازه خوانده شود. دلیل کارت فقط از شرط واقعی ساخته می‌شود. فعالیت فعالِ منقضی‌نشده نیز از پیشنهاد و تعویض کنار گذاشته می‌شود.

برای بیرون و سرپوشیده، فقط محل امن و مجاز از قبل در دسترس فرض می‌شود و این شرط در پرسش و جزئیات صریح است؛ هیچ محل، مسیر، قیمت یا زمان سفر تازه حدس زده نشده. فعالیت وابسته به روز/هوای مناسب با unknown رد می‌شود. [گزارش 22](22-catalog-coverage.md) ۶۴۸ ترکیب پایه را می‌شمارد؛ این نتیجه تضمین همهٔ blocked tagها، تعویض‌های نامحدود یا جذابیت برای همه نیست. ارزیابی جذابیت همچنان با بازخورد واقعی و review پیش از عرضه است. وابستگی، persistence یا provider تازه اضافه نشده است.

## تصمیم مالک: یک پیشنهاد، شش تعویض، نیاز جاری و برگشت — ۹ نوامبر ۲۰۲۶

مالک نمایش یک پیشنهاد با تا شش تعویض، افزودن دو سؤال برای نیاز فعلی و تقدم بُعدی که بیشتر انتخاب شده را خواست؛ سپس مرور پیشنهادهای قبلی را اضافه کرد. [23](23-single-suggestion.md) تصمیم جاری و مقدم بر شش کارت/سه slate قدیمی است. یک نوبت فقط یک session دارد؛ شش تعویض تازه حداکثر هفت snapshot می‌سازد و مرور قبلی/بعدی هیچ سهمیه‌ای مصرف نمی‌کند. گزینهٔ تازه فقط در انتهای تاریخچه است و کارت برگشتی پس از کنترل سرور قابل شروع می‌شود.

تصمیم مهندسی برگشت‌پذیر: نیاز اعلام‌شدهٔ همین نوبت مقدم بر سابقه است تا ترجیح قدیمی درخواست تازه را کنار نزند؛ دو پاسخ وزن ۰٫۶ و ۰٫۴ دارند. انتخاب به‌معنای اولین شروع موفق در هر نوبت است، مستقل از لغو بعدی؛ کلیک و مرور یا تکرار یک نوبت رأی را زیاد نمی‌کند. بُعد از snapshot تجربه خوانده می‌شود. نیاز نامعلوم fallback به goal و سپس سابقه دارد. مدل، سرویس، زیرساخت یا persistence تازه لازم نشد؛ اطلاعات در ماک و با restart موقتی‌اند.

## ADR19 — تصمیم مالک: MongoDB واقعی روی شبکهٔ عمومی — ۹ نوامبر ۲۰۲۶

مالک صریحاً ماک را لغو و URI دیتابیس عمومی Liara را برای همهٔ اجراها، حتی localhost، تعیین کرد. ADR16 و سند21 دیگر دستور جاری نیستند؛ مرجع [24](24-mongodb-storage.md) است. فقط DATA_BACKEND=mongo، بدون fallback؛ URI واقعی فقط `.env` سمت سرور. PyMongo 4.19.0 و dnspython 2.9.2 پس از بررسی منابع رسمی pin شدند؛ نصب در این محیط با DNS ناموفق بوده است.

تصمیم مهندسی: collection مستقل، UUID→_id، BSON UTC، ایندکس‌های واقعی، transaction snapshot/majority و سند محافظ سراسری برای حفظ قیود هم‌زمانی. writable replica-set primary لازم است؛ standalone به‌جای نوشتن غیراتمیک fail-fast می‌شود. directConnection برای ثابت‌ماندن روی endpoint عمومی فعال است؛ انتخاب replica/private member انجام نمی‌شود. توپولوژی و نسخهٔ زنده احراز نشده‌اند و سرویس Liara تغییر داده نشده است.

CSRF_HMAC_SECRET ثابت در تنظیمات، import دسته‌ای بی‌تکرار، بستن client و health واقعی اضافه شدند. runtime حافظه‌ای حذف و double فقط برای تست تزریق می‌شود. یک process و worker داخلی حفظ می‌شوند. اجرای هفت integration زنده و backup/restore/retention عملیاتی هنوز تأیید نشده‌اند؛ این برش استقرار عمومی را فعال نمی‌کند.

## تشخیص خطای اتصال پس از لاگ v7 — ۹ نوامبر ۲۰۲۶

v7 نخستین ping را ناموفق گزارش کرد، درحالی‌که adapter علت PyMongo را به پیام عمومی تبدیل می‌کرد. تصمیم برگشت‌پذیر: factory اتصال مشترک و دسته‌بندی امن خطا با مرحله و کد عددی، بدون متن خام driver یا URI؛ فرمان مستقل diagnose-db فقط خواندنی و بدون runner. شرط replica-set/transaction و endpoint عمومی تغییر نمی‌کنند و علت auth/network/TLS حدس زده نمی‌شود. خطای DNS این محیط مانع بررسی تنظیمات زنده است؛ اصلاح گزارش خطا ادعای رفع اتصال سرویس نیست. جزئیات در سند24/25 ثبت شده است.

## ADR20 — Docker لیارا به درخواست مالک — ۹ نوامبر ۲۰۲۶

مالک پس از اتصال Mongo، Dockerization برای استقرار در لیارا را خواست. [25](25-liara-docker.md) مرجع جاری است و محدودیت production-disabled برش قبل را جایگزین می‌کند. انتخاب برگشت‌پذیر: یک ایمیج چندمرحله‌ای، Python3.14.10 و Node22.23.4 از تگ رسمی ثابت، Next standalone و یک Uvicorn worker با job runner داخل آن؛ بدون proxy/صف/DB زیرساختی تازه. پورت عمومی3000 و API فقطloopback8000 است؛ Mongo همیشه endpoint عمومی قبلی است.

launcher با کتابخانهٔ استاندارد پایتون هر دو process group را مدیریت، خروج یکی را خطای کانتینر و SIGTERM را shutdown هماهنگ می‌کند. health check Docker و لیارا از وب تا API و ping DB را بررسی می‌کنند. APP_ENV=production فقط با originHTTPS معتبر است و کوکی Secure/HttpOnly/host-only صادر می‌شود. محیط Next فهرست مجاز و بدون secretهای API است. فرمان مستقل تغییر نقش از shell خصوصی بدون ساخت worker اضافه، با audit و revoke نشست، افزوده شد.

برای حفظ فرض یک worker، فقط یک نمونه و استقرار بدون اختلال خاموش؛ مستندات رسمی لیارا overlap پیش‌فرض را تأیید می‌کند. ZIP آپلود با فهرست مجاز و بدون .env/credential/buildهای محلی ساخته می‌شود. مجوز عرضهٔ محتوای demo، SMTP، حذف/export و backup جعل نشده‌اند. Docker daemon در محیط permission denied و DNS شبکه همچنان مانع آزمون زنده است؛ ساخت سورس وب و تست‌های آفلاین از build/run واقعی ایمیج تفکیک می‌شوند.

اصلاح مبتنی بر اجرای مالک در همان روز: release با startPeriod=180000 و سقف واقعی3000 رد شد، هرچند upload موفق بود. مقادیر liara.json به startPeriod180/interval30/timeout5 با مقیاس مثال رسمی اصلاح شدند؛ متن ms مستندات برای تبدیل قبلی کافی نبود و واحد مؤثر سرویس هنوز اندازه‌گیری نشده است. Docker HEALTHCHECK و startup launcher همچنان۱۸۰ثانیه صریح دارند. app=shadophena از انتخاب واقعی مالک ثبت شد؛ Git اختیاری metadata است و خطای debug آن مانع upload نبود. پذیرش مجدد release هنوز تأیید نشده است.

اصلاح دوم با گزارش build مالک: npm ci به‌علت۲۳placeholder پلتفرمی Sharp و dependencyهای غایب wasm/emnapi در lockfile خطای EUSAGE داد. lockfile در پوشهٔ بدون node_modules با npm/cache بازسازی و metadata توزیع تکمیل شد؛۱۳۷رکورد کامل، بدون تغییر نسخه‌های قبلی یا package.json. نصب تمیز آفلاین و Sharp واقعی موفق شدند؛۱۸تست، typecheck و standalone build روی نصب تازه با کپی فقط SWC هم‌نسخهٔ خارج از cache موفق بودند. Docker همچنان npm ci دارد؛ lockfile با npm install زمان build یا ارتقای بی‌دلیل npm دور زده نمی‌شود. جزئیات محدودیت نصب آفلاین و نسخهٔ npm در سند25 است.

اصلاح سوم با لاگ v6 مالک: شروع هم‌زمان API و Web و probe از proxy پیش از پایان lifespan، ECONNREFUSED پورت8000 را تولید می‌کرد. launcher به startup مرحله‌ای API-ready→Web تغییر کرد؛ health check نیز نخست API مستقیم و سپس proxy را می‌سنجد. args صریح لیارا launcher را اجرا می‌کند؛ APIserve بدون console و با log مراحل Mongo/seed/runner و خروجی unbuffered اضافه شد. شکست API به فرانت آمادهٔ ظاهری تبدیل نمی‌شود. تست‌های process واقعی، ترتیب، timeout، شکست و shutdown را پوشش دادند؛۱۰۱موفق و۷skip. لاگ فرانت به‌تنهایی علت احتمالی شکست API را اثبات نمی‌کند و دسترسی مستقیم لاگ در محیط با DNS ناموفق بود؛ اتصال DB یا رفع خطای زنده جعل نمی‌شود.

اصلاح تنظیمات پس از لاگ v12 مالک: code18 در ping، رد احراز هویت در runtime را نشان می‌دهد؛ URI مصرف‌شده و علت دقیق بدون خواندن محیط لیارا معلوم نیست. اطلاعات محرمانهٔ `.env` نباید برای رفع خطا وارد Docker/ZIP شوند. ابزار مستقل `scripts/sync-liara-mongo.py` با کتابخانهٔ استاندارد، همان URI عمومی فایل را در متغیر زمان اجرای برنامه ثبت و readback می‌کند؛ سایر متغیرها حفظ می‌شوند و اعتبارنامه چاپ نمی‌شود. اجرای واقعی ابزار در نخستین GET به‌علت DNS این محیط متوقف شد و هیچ تغییری در لیارا ارسال نشد؛ آماده‌بودن ابزار به‌معنی رفع auth سرور نیست. جزئیات و نتیجهٔ۲۶تست هدفمند در سند25 ثبت است.

دامنهٔ production به درخواست صریح مالک پس از رفع مانع Mongo: `https://shadophena.liara.run` پیش‌فرض Docker و loader production است؛ originهای دیگر فقط با تنظیم صریح APP_ORIGIN جایگزین می‌شوند. loader قالب‌های معادل origin مرورگر را canonical می‌کند، اما مبدا درخواست همچنان با allowlist دقیق سنجیده می‌شود. به Host و headerهای proxy برای گسترش مجوز اعتماد نمی‌شود. متن «آدرس محلی» از خطای مشترک حذف و origin مؤثر بدون secret در startup ثبت می‌شود. متغیر runtime بر پیش‌فرض ایمیج مقدم می‌ماند؛ اصلاح مقدار موجود لیارا در این محیط به‌علت DNS اعمال نشد. تست HTTPS روی دامنهٔ واقعی با store تزریق‌شده موفق بود؛ جزئیات و فرمان اصلاح محیط در سند25 است.
