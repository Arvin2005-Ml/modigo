# گزارش بررسی بستهٔ مشخصات

وضعیت جاری ذخیره‌سازی در [سند24](24-mongodb-storage.md) و استقرار Docker در [سند25](25-liara-docker.md) است؛ بخش‌های ماک این گزارش تاریخی‌اند. بستهٔ Markdown همراه با تغییر جاری دوباره ساخته شد و شامل ۳۶ فایل منبع README/AGENTS، docs و content است؛ اطلاعات محرمانه و کد اجرایی داخل آن ZIP نیستند. بستهٔ مستقل سورس استقرار `dist/funilo-liara.zip` با `scripts/package-deploy.py` ساخته می‌شود و با بستهٔ مستندات تفاوت دارد.

تاریخ گزارش اولیه:۶نوامبر۲۰۲۶. این بخش گزارش تحویل اولیهٔ Markdown است؛در آن زمان اپلیکیشن،server،پایگاه داده و اتصال پولی مدل ساخته یا اجرا نشده بودند. وضعیت جدید پیاده‌سازی و ماک در انتهای سند آمده است.

## بررسی‌های انجام‌شده

| بررسی | نتیجه |
| --- | --- |
| تعداد فایل‌های Markdown تحویلی |۳۱فایل:دو فایل ریشه،۲۱سند در docs و۸فایل در content |
| تعداد بذرها |۴۵۰؛دقیقاً۷۵در هر یک از شش فایل |

این بررسی‌ها با اسکریپت موقت روی فایل‌ها انجام شده‌اند؛unit test اپلیکیشن یا تضمین صحت همهٔ تصمیم‌های محصول نیستند. تست‌های نرم‌افزار برای ایجنت در14 تعریف شده‌اند. هیچ secret واقعی در نمونه‌های پیکربندی نیست؛مقادیر placeholder و نام مدلِ اعلام‌شدهٔ مالک‌اند.

## موارد عمداً تأییدنشده

پشتیبانی زندهٔ GapGPT از مدل و پارامترها؛دقت زمانی و اجراییِ همهٔ بذرها؛عدم هم‌پوشانی معنایی بانک؛نرخ موفقیت توصیه‌ها؛نام نهایی برند و متن حقوقی. این‌ها باید در smoke test،review محتوایی و پایلوت حل شوند،نه با موفقیت ساختگی. شش نمونهٔ پخته تألیفی‌اند؛برای demo نرم‌افزار حداقل۲۴مورد باید در مرحلهٔ پیاده‌سازی تکمیل و بازبینی شود.

بستهٔ ZIP همراه،کپی همین۳۱فایل است و دستور شروع در `docs/17-agent-prompt.md` قرار دارد. ایجنت برای ساخت ابتدا README و AGENTS را بخواند؛تغییرات آینده در منبع Markdown اعمال و ZIP دوباره ساخته شود.

## به‌روزرسانی فاز ماک

با افزوده‌شدن سند21،بستهٔ فعلی۳۲فایل Markdown دارد و ZIP از نسخهٔ جاری دوباره ساخته شد. دستور مالک برای عدم اتصال واقعی Mongo در معماری،مدل داده،API،هویت،گیمیفیکیشن،آزمون،اجرا،بک‌لاگ و پرامپت ایجنت اعمال شده است. کد پایهٔ storage و env نمونه نیز در workspace قرار دارند؛ZIP مشخصات فقط Markdownها را حمل می‌کند.

تست کد فعلی:۱۳تست unittest موفق،شامل۶فیلتر و۷storage. تست storage اتصال شبکه‌ای را با ممنوع‌کردن socket کنترل می‌کند و rollback و نمونهٔ پایان هم‌زمان را می‌سنجد؛این نتیجه به‌معنای ساخته‌شدن API یا اعتبارسنجی Mongo واقعی نیست. قواعد تعداد۴۵۰بذر،۷۵هر بُعد،لینک‌ها و JSONهای نمونه نیز حفظ شده‌اند.
