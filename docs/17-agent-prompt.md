# پرامپت آماده برای ایجنت کدنویسی

متن زیر را همراه همین پوشه به ایجنت بده. پیاده‌سازی آغاز شده و تصمیم جاری مالک اتصال MongoDB واقعی روی endpoint عمومی، حتی برای localhost است؛ سند24 بر تصمیم قبلی ماک مقدم است.

```text
فانیلو را بر اساس این مخزن پیاده‌سازی کن. هدف، یک محصول فارسی و RTL برای
پیشنهاد تفریح است: احراز هویت، پرسش‌های کوتاه، حداکثر شش انتخاب متناسب،
جزئیات اجرایی،ذخیره،شروع/پایان،بازخورد اختیاری،سابقه و گیمیفیکیشن؛
به‌علاوه پنل editor/admin و ایجنت پختن محتوای خام.

ابتدا AGENTS.md و README.md و ترتیب خواندن آن را رعایت کن.
Frontend: Next.js App Router + React + TypeScript + Tailwind.
Backend: FastAPI، مونولیت ماژولار با MongoDB واقعی روی endpoint عمومی.
DATA_BACKEND=mongo؛ URI از .env/محیط سرور، هیچ secret در web یا سند نگذار.
Mongo محلی، هاست خصوصی و fallback حافظه‌ای نداریم. یک process API و job runner
داخل آن؛ transaction و index واقعی لازم‌اند. ابتدا سند24 و محدودیت تأیید زنده
را بخوان. حساب، نشست، تاریخچه و کاتالوگ با restart حفظ شوند.
Flask،microservice،vector DB و مدل trainشده در نسخهٔ اول اضافه نکن.

طراحی نرم،گرم،خودمانی و بسیار مینیمال سند03 یک الزام است،نه پرداخت نهایی.
شش کارت انتخاب جایگزین‌اند؛ از هر بُعد یک کارت را به زور تحمیل نکن.
DRAMMA دسته‌بندی metadata است. پیشنهاد بدون دیتای آموزشی با فیلتر سخت،
امتیازدهی و تنوع انجام می‌شود. وقتی کمتر از شش نتیجه معتبر هست،صادقانه همان
تعداد را نشان بده و تغییر شرایط را به انتخاب کاربر بسپار.

ایجنت محتوا در پشت‌صحنه و با تأیید ادمین کار می‌کند؛ خروجی مستقیم منتشر نشود.
Provider اعلام‌شده GapGPT،base_url=https://api.gapgpt.app/v1 و مدل دقیق
gapgpt-deepseek-v4.1-flash است. سازگاری Responses،reasoning high و schema
را با smoke test جدا بسنج؛ تعویض پنهانی مدل نکن. API key فقط server-side.
بدون کلید provider demo و fixture روشن داشته باش؛ CI وابسته به شبکهٔ مدل نباشد.

۴۵۰بذر در content را draft وارد کن،نه منتشرشده. برای demo حداقل۲۴محتوای
کامل و بازبینی‌شده بساز؛ نمونه‌های پخته مرجع کیفیت‌اند.
قرارداد انواع05،API06،الگوریتم07 و امتیاز11 را هماهنگ پیاده کن.
کنترل مالکیت،session/CSRF،قیدهای یکتا،اتمیک‌بودن پایان با transaction Mongo و
idempotency الزامی‌اند. API و منطق واقعی باشند؛persistence واقعی است؛ double فقط در تست تزریق شود.

طبق بک‌لاگ16،اول یک مسیر عمودی واقعی و زیبا بساز،بعد بقیهٔ P0 را تکمیل کن.
ابهام‌های برگشت‌پذیر را با قضاوت مهندسی حل و در18 ثبت کن؛ برای تصمیمی که
با اسناد حل می‌شود کار را متوقف نکن. نسخه‌های وابستگی را بررسی و pin کن.
پس از هر برش،تست مناسب را اجرا و وضعیت واقعی را گزارش کن. موفقیت ساختگی،
دکمهٔ بدون عملکرد و اتصال مدل آزمون‌نشده را به‌عنوان تکمیل‌شده تحویل نده.

تحویل فاز فعلی: کد،lockfile،راهنمای اجرا با Mongo عمومی و بدون Mongo محلی/Docker،seed و importer،
OpenAPI/client،تست‌های ضروری،راهنمای اجرای بدون کلید،CLI ادمین،runbook،
گزارش تست و screenshot سؤال‌ها/نتایج/جزئیات. همهٔ P0ها را تکمیل کن و
محدودیت‌های واقعاً باقی‌مانده را روشن بنویس.
```
