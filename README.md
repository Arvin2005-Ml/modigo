# فانیلو — بستهٔ طراحی و تحویل به ایجنت کدنویسی

نسخهٔ سند: 1.6 — ۹ نوامبر ۲۰۲۶. زبان محصول: فارسی، راست‌به‌چپ. نام «فانیلو» فعلاً نام کاری است.

فانیلو کمک می‌کند آدم‌ها با توجه به وقت، انرژی، همراه، محیط و بودجه‌شان یک تفریح واقعاً قابل انجام پیدا کنند. چند سؤال کوتاه، یک پیشنهاد آمادهٔ اجرا با حداکثر شش تعویض و امکان برگشت به پیشنهادهای دیده‌شده، انتخاب یک تجربه و یک بازخورد اختیاری. محصول قرار نیست وقت آزاد را به تکلیف تبدیل کند.

این مخزن ابتدا به‌صورت بستهٔ مشخصات تهیه شد و اکنون پیاده‌سازی اولیهٔ آن آغاز شده است. اتصال واقعی به GapGPT، آزمون کامل محصول و استقرار هنوز انجام نشده‌اند. وضعیت اجرایی فعلی در انتهای این فایل آمده است.

## تصمیم‌های اصلی

- فرانت: Next.js App Router، React، TypeScript و Tailwind CSS؛ طراحی اختصاصی فارسی و موبایل‌محور.
- بک‌اند: FastAPI و MongoDB واقعی روی endpoint عمومی Liara، حتی در localhost؛ `DATA_BACKEND=mongo` تنها backend اجرایی است. URI محرمانه در `.env` سمت سرور و مرجع اجرا سند24 است.
- شروع پیشنهاددهی: قواعد، متادیتای محتوا، امتیازدهی قابل توضیح و تنوع؛ بدون نیاز به دیتای آموزش.
- ایجنت محتوا: تبدیل ایدهٔ خام به تجربهٔ اجرایی در پشت صحنه، با اعتبارسنجی و انتشار ادمین. تجربهٔ اصلی به آنلاین بودن مدل وابسته نباشد.
- احراز هویت محلی: ایمیل و رمز عبور، بدون تأیید ایمیل، با نشست سمت سرور؛ حساب کاربری برای دریافت پیشنهاد و ذخیرهٔ سابقه لازم است.
- گیمیفیکیشن: تجربه‌های انجام‌شده، نشان‌های محدود و مسیر اکتشاف؛ بدون جریمهٔ غیبت و رقابت عمومی.
- ۴۵۰ بذر پیشنهادی: ۷۵ مورد برای هر بُعد. فایل مالک به عنوان بذر خام وارد می‌شود؛ هیچ‌کدام خودکار منتشر نمی‌شوند.

## قاعدهٔ رفع اختلاف

آخرین تصمیم صریح مالک محصول مقدم است. سپس قرارداد انواع در `05` و قرارداد HTTP در `06` برای پیاده‌سازی الزام‌آورند. الگوریتم در `07` و قواعد امتیاز در `11` مرجع منطق‌اند. بقیهٔ متن‌ها مثال و توضیح این قراردادها هستند. اختلاف کشف‌شده باید اصلاح و در `18` ثبت شود؛ حدس پنهانی ممنوع.

## تعریف تحویل

نرم‌افزار قابل اجرا با دادهٔ نمایشی، تست‌های معنادار، راهنمای راه‌اندازی، بانک ۴۵۰تایی واردشده به‌صورت پیش‌نویس و حداقل ۲۴ تجربهٔ پختهٔ قابل نمایش. انتشار عمومی کل بانک فقط پس از بازبینی محتوایی؛ وجود شش جایگزین تازه برای هر ترکیب تضمین نشود و حالت کمبود نتیجه پیاده شود؛ مرور پیشنهادهای قبلی سهمیه مصرف نکند.

## استقرار Docker در لیارا

Dockerfile ریشه، Next standalone و API را با کاربر غیر root در یک کانتینر اجرا می‌کند؛ پورت عمومی **3000** و API داخلی `127.0.0.1:8000` است. MongoDB همان endpoint عمومی مالک است. [راهنمای کامل لیارا](docs/25-liara-docker.md) مرجع جاری production است.

```sh
python3 scripts/package-deploy.py
```

فایل **`dist/funilo-liara.zip`** را در برنامهٔ Docker لیارا آپلود کنید. قبل از اجرا `APP_ORIGIN` را روی دامنهٔ HTTPS بدون `/` انتهایی، `MONGODB_URI` را روی URI محرمانهٔ فعلی و `CSRF_HMAC_SECRET` را روی کلید ثابت سرور تنظیم کنید. رمزها وارد ZIP و ایمیج نمی‌شوند. **استقرار بدون اختلال را خاموش و تعداد نمونه را۱ نگه دارید**؛ اجرای محلی روی همان DB هم نباید هم‌زمان فعال باشد. health check پورت وب تا Mongo واقعی را می‌سنجد.

دامنهٔ اصلی و پیش‌فرض production **`https://moodigo.ir`** است. اگر خطای ناهماهنگی آدرس صفحه برگشت، مقدار runtime را با `liara env:set APP_ORIGIN=https://moodigo.ir --app shadophena --force` بررسی و اصلاح کنید؛ متغیر موجود لیارا بر پیش‌فرض ZIP مقدم است. اطلاعات Mongo و کلید CSRF حفظ شوند.

برای CLI: `liara deploy --app shadophena --platform docker --port 3000`. شناسهٔ برنامه طبق انتخاب مالک در liara.json ثبت شده است. برای ادمین در کنسول خصوصی کانتینر: `python -m app.cli role EMAIL admin` و سپس ورود مجدد. build/run کامل ایمیج و اتصال زنده در این محیط هنوز تأیید نشده‌اند؛ جزئیات آزمون و محدودیت‌ها در سند25 است.

برای اصلاح `MONGODB_URI` زمان اجرای لیارا از روی اطلاعات محرمانهٔ `.env` محلی، در محیط دارای شبکه و نشست `liara login` اجرا کنید: `python3 scripts/sync-liara-mongo.py`. ابزار فقط URI عمومی را تنظیم می‌کند، سایر متغیرها را حفظ و نتیجه را دوباره بررسی می‌کند؛ رمز در خروجی یا ZIP قرار نمی‌گیرد. تغییر تنظیمات ممکن است برنامه را restart کند. `--check` فقط مقایسه می‌کند. احراز هویت و آمادگی زنده پس از تنظیم باید جدا بررسی شوند؛ [جزئیات خطای v12](docs/25-liara-docker.md#اصلاح-تنظیمات-احراز-هویت-پس-از-لاگ-v12--۹-نوامبر-۲۰۲۶).

## اجرای محلی نسخهٔ در حال ساخت

حساب‌ها، نشست‌ها، سوابق، محتوا و صف در MongoDB واقعی روی `olympus.liara.cloud:34468/my-app` ذخیره می‌شوند. حتی اجرای localhost به همین endpoint عمومی متصل می‌شود. `.env` ریشه با URI مالک و کلید ثابت CSRF آماده شده و وارد نسخه‌بندی نمی‌شود؛ برای محیط دیگر `.env.example` را با مقادیر محرمانه تکمیل کنید. برنامه `.env` را خودکار می‌خواند. Mongo محلی و Docker لازم نیستند؛ یک API process و worker داخل همان process حفظ شده‌اند.

**وضعیت اتصال:** نصب driver و اتصال زنده در محیط فعلی به‌علت دسترسی DNS تأیید نشده‌اند. MongoDB باید writable replica-set primary با پشتیبانی تراکنش باشد؛ اگر سرویس standalone باشد startup خطای صریح می‌دهد و حافظه جایگزین نمی‌شود. نسخهٔ `9.0.2` اعلام مالک است و هنوز از سرور خوانده نشده. جزئیات و محدودیت‌ها در [سند24](docs/24-mongodb-storage.md) است؛ استقرار نسخهٔ فعلی با درخواست بعدی مالک در [سند25](docs/25-liara-docker.md) آماده شده است.

پیش‌نیازها Python 3.14 و Node.js 22 یا بالاترند. نسخه‌های پایتون در `apps/api/requirements.lock` ثابت شده‌اند؛ از ریشهٔ مخزن:

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install -r apps/api/requirements.lock
PYTHONPATH=apps/api .venv/bin/python -m app.cli check-db
PYTHONPATH=apps/api .venv/bin/python -m app.cli
```

در یک ترمینال دیگر:

```sh
cd apps/web
npm ci
npm run dev
```

سپس مرورگر را روی `http://127.0.0.1:3000` باز کنید. در اجرای محلی، `localhost` و `127.0.0.1` با همان پورت هر دو مجازند، ولی کوکی‌های جداگانه دارند؛ نشانی‌های دیگر باید دقیقاً با `APP_ORIGIN` یکی باشند. هر دو ترمینال باید هم‌زمان باز بمانند. اگر Next خطای `ECONNREFUSED 127.0.0.1:8000` می‌دهد، فرایند API اجرا نیست یا بالا نیامده است؛ خطای ترمینال API را بررسی کنید. ثبت‌نام بدون تأیید ایمیل است و بلافاصله وارد حساب می‌شوید. برای دسترسی ادمین، در **کنسول همان فرایند API** دستور `role your-email@example.com admin` را بدهید و دوباره وارد شوید. تغییر نقش از HTTP در دسترس نیست. بازیابی رمز در این محیط صرفاً از طریق صندوق محلی اپراتور انجام می‌شود و ایمیل واقعی ارسال نمی‌شود.

بانک ۴۵۰تایی مالک به شکل پیش‌نویس خام وارد می‌شود. کاتالوگ محلی اکنون **۱۱۳ تجربهٔ فعال تألیفی** دارد: شش نمونهٔ اصلی و ۱۰۷ تجربهٔ تازه در `content/demo-catalog.json`. هجده نمونهٔ اولیهٔ مشابه و خیلی کلی به‌صورت archived و غیرفعال نگه داشته شده‌اند. محتوای demo تأیید انتشار عمومی ندارد و خروجی مدل نیست. شش بذر مشخص (`D-001`, `R-005`, `A1-001`, `M1-010`, `M2-004`, `A2-002`) نمونهٔ آمادهٔ محلی برای دکمهٔ پخت دارند. سایر بذرها در حالت demo پیام نبود نمونه می‌دهند؛ همهٔ خروجی‌های پخت تا تأیید انسان پیش‌نویس می‌مانند.

دو سؤال «الان بیشتر چی کم داری؟» و «دوست داری از این وقت چی با خودت ببری؟» نیاز جاری را مشخص می‌کنند؛ پاسخ نامعلوم هم معتبر است. الگوریتم ابتدا نیاز همین نوبت، سپس بُعدی که کاربر بیشتر شروع کرده و بعد تناسب فعالیت را اولویت می‌دهد. هر نوبت حداکثر یک رأی از اولین شروع موفق دارد؛ مرور، تعویض و ذخیره رأی نیستند. این ترجیح و سابقه در MongoDB حفظ می‌شوند.

صفحهٔ نتیجه یک کارت و تا شش جایگزین تازه دارد. دکمه‌های «پیشنهاد قبلی» و «پیشنهاد بعدی» دیده‌شده‌ها را بدون مصرف سهمیه مرور می‌کنند؛ کارت قبلی پس از برگشت قابل شروع است. جای مرور و شمارنده در سرور می‌مانند و با تازه‌کردن صفحه حفظ می‌شوند. بعد از اتمام سهمیه هم مرور ممکن است.

در پایان سؤال‌ها، انتخاب سلیقه و وسایل دم‌دست اختیاری است؛ کاغذ، قلم، گوشی و سایر وسایل خودکار فرض نمی‌شوند. انتخاب‌های حساب پیش‌فرض‌اند و انتخاب خالی صریح فقط برای همان نوبت آن‌ها را کنار می‌گذارد. برای فعالیت بیرونی وابسته به هوا یا روز، همان‌جا شرایط را مشخص کنید. پیشنهادهای بیرون و سرپوشیده برای محل امن و مجازِ از قبل در دسترس‌اند، نه مکان یا مسیر تأییدنشده.

برای بارگذاری بذرهای تازه، API را دوباره راه‌اندازی کنید؛ import بی‌تکرار است و حساب‌ها، نشست‌ها و ویرایش‌ها در Mongo می‌مانند. نیازی به کلید مدل نیست؛ اتصال Mongo واقعی لازم است. [گزارش پوشش](docs/22-catalog-coverage.md) با این دستور بازتولید می‌شود:

```sh
PYTHONPATH=apps/api .venv/bin/python -m app.modules.recommendations.coverage
```

برای امتحان اختیاری GapGPT، متغیرهای `LLM_PROVIDER=gapgpt` و `GAPGPT_API_KEY` را فقط در محیط فرایند سرور تنظیم کنید. endpoint و مدل پیش‌فرض همان نمونهٔ مالک هستند. سازگاری Responses و مدل با GapGPT هنوز با کلید واقعی آزمایش نشده است. خطای احراز هویت provider صف را متوقف می‌کند؛ پس از اصلاح تنظیمات و راه‌اندازی مجدد، یا رفع مشکل و دستور `resume-provider` در همان کنسول، دوباره امتحان کنید. jobهای running هنگام restart با WORKER_INTERRUPTED شکست می‌خورند؛ queuedها و داده‌های محصول باقی می‌مانند. صندوق ایمیل اپراتور همچنان موقت است.

این تنظیم دستیار تفریح را هم از `demo` به GapGPT می‌برد. دستیار برای راهنما و چت از Chat Completions و برای تصویر از Images API استفاده می‌کند. مدل‌های مجزا، میزبان تصویر و روش تست در [سند44](docs/44-activity-assistant-frontend.md#اجرای-بکاند-برای-تست) آمده‌اند. درخواست راهنما و تصویر وابستگی مسیر پیشنهاد و شروع تجربه نیست.

تست‌های API و دامنه شامل فیلترها، نشست و CSRF، مجوز و مالکیت، هم‌زمانی پایان، انتشار، لغو تولید و جلوگیری از بازنویسی پیش‌نویس هستند. در برش ۹ نوامبر، ۷۹ تست پایتون و ۱۸ تست فرانت، `npm run typecheck` و `npm run build` موفق شدند. تست‌ها تک‌پیشنهاد، شش تعویض، مرور و شروع کارت قبلی، حفظ جای مرور بعد از reload، رقابت درخواست‌ها، CSRF، مالکیت، withdrawal و یادگیری از انتخاب‌ها را نیز بررسی می‌کنند. تست فرانت شامل رندر واقعی کامپوننت پیشنهاد است. پوشش ۶۴۸ ترکیب پایه و رتبه‌بندی ۴۸۰ ترکیب کوتاه با انرژی/حال متفاوت نیز در تست‌ها بررسی می‌شود. آزمون end-to-end مرورگر و بازبینی بصری تغییر تازه اجرا نشده‌اند؛ جذابیت برای کاربران هنوز به بازخورد واقعی نیاز دارد. این برش برای استقرار عمومی فعال نشده است. حذف و export حساب، سنجش محصول، برخی ابزارهای ادمین و پوشش کامل خطاهای provider باقی مانده‌اند؛ وضعیت جزئی در [بک‌لاگ](docs/16-backlog.md) ثبت شده است. [سند MongoDB واقعی](docs/24-mongodb-storage.md) جایگزین دستورهای ماک شده است.

## برش اتصال MongoDB — ۹ نوامبر ۲۰۲۶

تنها backend اجرایی Mongo واقعی است؛ تنظیم محرمانه، ساخت ایندکس، transaction، CAS، health check، بستن client، CSRF ثابت و import دسته‌ای پیاده شده‌اند. PyMongo 4.19.0 و dnspython 2.9.2 در lockfile pin هستند. نتیجهٔ تست‌های آفلاین و تفاوت آن با آزمون زنده در سند24 ثبت شده است. برای اجرای آزمون واقعیِ اختیاری روی دیتابیس‌های موقت و جدا از my-app:

```sh
RUN_MONGODB_TESTS=1 PYTHONPATH=apps/api .venv/bin/python -m unittest discover -s apps/api/tests -p test_mongo_integration.py -v
```

در این محیط DNS برای registry و Liara در دسترس نیست؛ نصب وابستگی تازه، اتصال سرور، ساخت ایندکس زنده و این هفت آزمون هنوز تأیید نشده‌اند. دستور `check-db` اکنون به‌علت نصب‌نبودن driver ناموفق است؛ موفقیت تست آفلاین به‌معنای اتصال واقعی نیست.

## نتیجهٔ آزمون برش MongoDB — ۹ نوامبر ۲۰۲۶

۹۰ تست آفلاین پایتون موفق؛ هفت تست Mongo واقعی بدون opt-in صریح skip شدند (خروجی unittest: Ran 97, OK, skipped=7). ۱۸ تست فرانت، typecheck و build نیز موفق بودند. بررسی syntax پایتون و shell، لینک‌های داخلی و عدم کپی secret در کد/مستندات موفق بود. نصب driver از registry و اتصال endpoint Liara به‌علت DNS محیط تأیید نشد؛ check-db با پیام نصب‌نبودن PyMongo و exit1 متوقف شد. این نتایج تأیید ایندکس، transaction، نسخه یا ماندگاری روی سرور مالک نیستند. CI، E2E و بازبینی بصری این برش اجرا نشده‌اند.

## نتیجهٔ برش Docker لیارا — ۹ نوامبر ۲۰۲۶

۹۷ تست آفلاین پایتون موفق و۷ تست Mongo زنده skip شدند (Ran104، skipped=7). ۱۸ تست فرانت، typecheck و build مستقل Next موفق‌اند. آزمون‌های تازه HTTPS/CSRF و کوکی امن، خروج یک سرویس و توقف دیگری، timeout و جمع‌کردن processها، تغییر نقش CLI با audit/revoke و مرز بستهٔ آپلود را بررسی می‌کنند. ZIP۷۴فایلی ساخته و با آرشیو واقعیِ محلی Liara CLI تطبیق داده شد؛ استخراج سورس و راه‌اندازی composition root با store تزریق‌شدهٔ تست و همهٔ فایل‌های محتوا موفق بود. اسکن ZIP و build فرانت، credential تنظیم‌شدهٔ سرور را پیدا نکرد.

ساخت/run کامل Docker به‌علت permission denied روی daemon اجرا نشده است؛ bind پورت localhost نیز با Operation not permitted مسدود بود، پس smoke شبکه‌ای standalone و استقرار واقعی لیارا انجام نشدند. اتصال Mongo و تراکنش واقعی همچنان تأیید نشده‌اند. راه استقرار و محدودیت‌های محصول در [سند25](docs/25-liara-docker.md) آمده‌اند.

## اصلاح نصب تمیز فرانت برای لیارا — ۹ نوامبر ۲۰۲۶

با گزارش EUSAGE از build واقعی مالک، lockfile فرانت در پوشهٔ بدون node_modules بازسازی شد. ۲۳ رکورد ناقص پلتفرمی Sharp و dependencyهای wasm/emnapi تکمیل شدند؛ همهٔ۱۳۷بسته اکنون version/resolved/integrity دارند و هیچ نسخهٔ قفل‌شدهٔ قبلی تغییر نکرده است. Docker همچنان npm ci اجرا می‌کند.

نصب تمیز آفلاین با cache جدا موفق و Sharp0.35.5 قابل بارگذاری بود؛ سپس۱۸تست فرانت، typecheck و build standalone روی dependencyهای تازه‌نصب‌شده موفق شدند. فقط باینری SWC16.4.5 که tarball آن در cache نبود، برای build از نسخهٔ همسان نصب‌شدهٔ محلی کپی شد. npmCI محلی10.9.8 است؛ build گزارش‌شدهٔ لیارا npm10.9.9 دارد. build کامل ایمیج/دانلود آنلاین در این محیط تأیید نشده است. ZIP استقرار با lockfile جدید دوباره ساخته شد.

## تشخیص شکست اتصال Mongo در v7 — ۹ نوامبر ۲۰۲۶

نخستین ping در لاگ v7 شکست خورده؛ علت واقعی با پیام قدیمی قابل تشخیص نبود. اکنون دستهٔ امن خطا، مرحله و کد عددی سرور گزارش می‌شود و فرمان `python -m app.cli diagnose-db` برای تشخیص بدون نوشتن داده اضافه شده است. از shell برنامهٔ دارای سورس تازه: `liara shell --app shadophena --command "python -m app.cli diagnose-db"`. این فرمان API یا runner دوم نمی‌سازد؛ موفقیت آن تأیید ایندکس و commit نیست. راهنمای دسته‌ها و رفع تنظیمات در [سند25](docs/25-liara-docker.md) است. اتصال واقعی از این محیط به‌علت DNS تأیید نشده و رفع نهایی وابسته به علت گزارش‌شده از سرور است.

نتیجهٔ این اصلاح:۱۱۰تست آفلاین پایتون موفق و۷تست Mongo زنده skip شدند (Ran117). ۹تست تازه فرمان فقط‌خواندنی، دسته‌بندی امن، عدم افشای اطلاعات حساس، اعتبارسنجی URI و یکسان‌بودن گزینه‌های اتصال runtime/diagnostic را بررسی کردند. syntax پایتون موفق بود. اجرای محلی diagnose-db به‌علت نصب‌نبودن PyMongo با exit1 متوقف شد؛ اتصال زنده، build/run ایمیج و استقرار این تغییر هنوز تأیید نشده‌اند.

## اصلاح ترتیب startup در لیارا — ۹ نوامبر ۲۰۲۶

با گزارش ECONNREFUSED پورت8000، launcher اصلاح شد تا ابتدا API و Mongo آماده شوند و سپس Next اجرا شود. health check نیز تا قبل از آمادگی API از proxy فرانت عبور نمی‌کند. دستور launcher در args لیارا صریح و log مراحل startup API افزوده شد. در شکست/timeout API، فرانت شروع نمی‌شود و کانتینر ناموفق متوقف می‌شود. علت احتمالی شکست API از لاگ Next به‌تنهایی قابل تشخیص نیست؛ راه تشخیص در [سند25](docs/25-liara-docker.md) است.

۱۰۱تست پایتون موفق و۷تست Mongo واقعی skip شدند (Ran108)، شامل۱۰تست deployment برای ترتیب startup، شکست، timeout، shutdown و health مرحله‌ای. build/run واقعی این اصلاح و اتصال سرور همچنان از این محیط تأیید نشده‌اند؛ دسترسی لاگ مستقیم لیارا هم با خطای DNS ناموفق بود. بستهٔ ZIP با تغییرات تازه بازسازی شده است.
