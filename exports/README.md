# خروجی تفریح‌ها — ۱۱ نوامبر ۲۰۲۶

- `activities.csv`: همهٔ ۵۸۱ فعالیت تعریف‌شده برای ورود اولیه؛ ۴۵۰ بذر خام مالک و ۱۳۱ نمونهٔ پختهٔ نمایشی. تمام متادیتای موجود حفظ شده؛ متادیتای بانک در ستون‌های `source_metadata.*` و محتوای پخته در `content.*` است. آرایه‌ها JSON داخل سلول‌اند. فایل UTF-8 با BOM برای نمایش فارسی در Excel است؛ مقدار ثبت‌نشده خالی می‌ماند.
- `cooked-activities.json`: متن کامل و متادیتای ۱۳۱ نمونهٔ پخته در `activities`، شامل ۱۱۳ فعال و ۱۸ کنارگذاشته‌شده در تعریف اولیه. شش قالب آمادهٔ پخت بانک در `prepared_fixtures` جدا هستند؛ این شش قالب اثبات اجرای job یا انتشار بذر نیستند. متادیتای عمومی بانک، تعریف برچسب‌ها، تعدادها و محدودیت منبع نیز داخل فایل است.

منبع خروجی فایل‌های موجود پروژه و همان mapping واردکنندهٔ برنامه است. بانک Markdown تألیفی جایگزین، منبع import جاری نیست و دوباره شمرده نشده است. هیچ UUID دیتابیس یا زمان پخت حدس زده نشده است. `cooked_at=null` یعنی زمان واقعی پخت در منبع ثبت نشده؛ `exported_at` فقط زمان خروجی‌گرفتن است. `initial_state` و `initial_active` وضعیت ورود اولیه‌اند و وضعیت فعلی دیتابیس را اثبات نمی‌کنند. محتوای demo خروجی واقعی مدل یا دارای تأیید انتشار عمومی نیست.

فرمان بازتولید از ریشهٔ پروژه، با وابستگی‌های موجود API:

```sh
.venv/bin/python scripts/export-activities.py
```

این ابزار فقط فایل‌ها را می‌خواند؛ سرویس، job runner یا اتصال DB ایجاد نمی‌کند و تنظیمات محرمانه را نمی‌خواند. برای خروجی جاری MongoDB باید در محیط دارای driver و دسترسی عمومی، دادهٔ زنده جداگانه خوانده شود؛ fallback اجرایی افزوده نشده است.

بررسی این تحویل: تولید خروجی و بازخوانی CSV/JSON موفق بود؛ ۵۸۱ کلید یکتا، حفظ تک‌تک فیلدهای ۴۵۰ بذر، تطبیق کامل ۱۳۱ محتوای پخته و شش قالب با منابع و schema، تعداد ۱۱۳ فعال و ۱۸ archived، BOM فارسی و syntax اسکریپت بررسی و تأیید شدند. فرمان `diagnose-db` به‌علت نصب‌نبودن PyMongo ناموفق بود؛ خروجی زندهٔ MongoDB تهیه نشد. تست‌های کامل برنامه برای این خروجی مستقل اجرا نشدند.
